# 데일리 → 레퍼런스 자동 정리기

Jade님(채널톡 SDR)의 Obsidian 볼트에서, `02-daily/`의 데일리 노트를 읽어 레퍼런스 문서 체계에 반영하는 스킬이다.

> 볼트 규칙의 원본은 `README.md`다. 충돌 시 README가 우선한다.

## 0. 실행 전 필수 확인

1. **cwd가 볼트 루트인지 확인** (`README.md`와 `01-accounts/`가 보여야 함)
2. **git 체크포인트 생성** — 되돌릴 수 있게:
   ```bash
   git add -A && git commit -q -m "checkpoint: daily-ref 실행 전" || true
   git rev-parse --short HEAD
   ```
   해시를 사용자에게 알려준다.

## 2. 회사 블록 파싱

데일리 노트에서 회사 단위 블록을 3가지 패턴으로 인식한다.

| 패턴 | 형태 | 나오는 곳 |
|---|---|---|
| A | 한 줄 전체가 볼드인 회사명 → 다음 `---` 또는 다음 볼드 회사명까지 | 리드마켓 노트 |
| B | `### 회사명(별칭)` … 다음 `###` 까지 | 오후 스크럼 |
| C | `\| [[회사명]] \| 결과 \| 다음 액션 \|` | 콜 로그 표 |

**패턴 A의 실제 변형 — 전부 인식할 것:**
```
**더블유쇼핑** | 커머스                        ← 버티컬 있음
**팩플러스**                                  ← 버티컬 없음 ⚠️ 놓치기 쉬움
**[[베니토]]** | 커머스, 의류/패션              ← 이미 링크됨
**[[주식회사_크랩|주식회사 크랩]]** | B2B 솔루션  ← 표시텍스트 링크 ⚠️
**제타 (롯데마트)** | Commerce                 ← 괄호·공백 포함
```
- `| 버티컬` 은 **선택**이다. 없다고 건너뛰지 말 것.
- 링크가 걸려 있으면 `[[파일명|표시명]]` 에서 **파일명**을 회사 식별자로 쓴다.
**볼드 줄이지만 회사가 아닌 것 — 제외할 것.**
정규식은 일부러 넓게 잡으므로, 걸러내는 것은 판단의 몫이다. 실제 볼트에서 관찰된 오탐:

```
**Sales Message**      **Core Needs**       **Core needs - 라우팅**
**Risk**               **PAIN**             **pain)**
**Funnel**             **FS**               **8월 1주차**
**잘하는 사람**          **AI BPO**            **웹빌더사 경쟁사**
**daily scrum - 호텔 플레이북 공유**          **통신사 제공 CTI**
**지점 간의 대화를 팀챗으로**                  **경쟁사를 사용하고 있을 경우**
**# 제안서 flow**       **- 2) 알림톡·문자 등을 활용한 재구매 유도**
```

**판정 기준 3가지 (전부 만족해야 회사):**
1. 그 줄 아래에 **그 회사에 관한 딜 내용**이 이어지는가
2. 문장이 아니라 **고유명사**인가 (조사·서술어·물음표가 붙으면 회사 아님)
3. 섹션 라벨(`Core Needs`, `Sales Message`, `Risk`, `PAIN` 등)이나 이미 볼트에 있는 개념 노트 이름이 아닌가

애매하면 **생성하지 말고 사용자에게 묻는다.** 잘못 만든 딜 노트를 지우는 것보다 물어보는 비용이 싸다.

**회사 블록이 아닌 것** (= 딜 노트로 만들지 말 것):
- `# 오전 scrum` 아래의 일반 학습 내용 → 3-5의 플레이북 갱신 후보로만 처리
- 용어 설명, 경쟁사 일반 정보, Q&A 블록
- 이미 `[[링크]]`가 걸린 회사여도 블록 내용은 다시 읽어 **병합 대상**으로 삼는다

## 3. 회사별 처리

### 3-1. 내 딜 / 학습 딜 판정 ⚠️ 가장 중요

이 볼트의 핵심 규칙은 **"내 딜과 남의 딜을 절대 섞지 않는다"** 이다.

판정 순서 (위에서부터 먼저 맞는 것 적용):

1. 이미 `01-accounts/{회사}.md` 가 존재 → **내 딜**
2. 이미 `04-reference/deal-notes/{회사}.md` 가 존재 → **학습 딜**
3. 블록에 `[내딜]` 마커가 있음 → **내 딜**
4. **콜 로그 표(패턴 C)에 등장** → **내 딜** (내가 직접 전화했으므로)
5. 그 외 (리드마켓 블록, 오후 스크럼) → **학습 딜**

> 판정이 애매하면 **묻는다.** 잘못 넣으면 대시보드가 남의 일로 오염된다.
> 특히 "리드마켓에서 내 딜을 리뷰받은 경우"는 4·5번 규칙으로는 못 잡으니 반드시 확인한다.

### 3-2. 기존 노트가 있으면 → 병합 (절대 덮어쓰지 않음)

- 본문 섹션(`## Core Needs` / `## 전략` / `## Risk`)에 **새로운 내용만 추가**한다.
- **중복 금지**: 이미 있는 문장과 의미가 같으면 추가하지 않는다.
- 내 딜이면 `## 타임라인` 에 한 줄 추가: `- {날짜} {요약} — [[{데일리노트}]]`
- frontmatter는 **비어 있는 필드만** 채운다. 이미 값이 있으면 건드리지 않되, 명백히 갱신된 정보(단계 변화 등)는 사용자에게 확인 후 수정한다.

### 3-3. 없으면 → 신규 생성

**내 딜** → `01-accounts/{회사명}.md`
```yaml
---
type: account
company: {회사명}
vertical: "[[{버티컬}]]"
stage: "[[Open]]"
keyman:
keyman_contact: false
competitor: []
core_needs: []
next_action: {블록에서 추출한 다음 액션}
next_date: {명시된 날짜 / 없으면 3일 뒤}
first_touch: {데일리 날짜}
sf_link:
---
#account
```
본문: `## Core Needs` / `## 전략` / `## Risk` / `## 타임라인`

**학습 딜** → `04-reference/deal-notes/{회사명}.md`
```yaml
---
type: deal-note
company: {회사명}
vertical: "[[{버티컬}]]"
competitor: []
core_needs: []
owner: 선임 (리드마켓 리뷰 청취)
reviewed: {데일리 날짜}
source: "[[{데일리노트 파일명}]]"
---
#deal-note

> 📚 **학습 노트** — 내가 진행한 딜이 아니라 리드마켓 리뷰에서 들은 내용입니다. 참고·레퍼런스 용도.
```
본문: `## Core Needs` / `## 전략` / `## Risk` — **액션 필드(next_action·next_date) 절대 넣지 말 것.**

### 3-4. 파일명 규칙
- 공백은 언더바 `_` (`주식회사 크랩` → `주식회사_크랩.md`)
- 괄호 별칭은 제거하되 본문에 남긴다 (`제이비케이랩(셀메드)` → `제이비케이랩.md`)
- 링크는 표시 텍스트를 쓴다: `[[주식회사_크랩|주식회사 크랩]]`

### 3-5. 본문 작성 규칙
- **원문 표현을 최대한 보존**한다. 요약하되 고객 발언·수치·고유명사는 그대로.
- 고객 직접 발언은 `*"..."*` 로 인용.
- Lost 딜이면 반드시 **사유 + 재접점 조건**을 `## Risk` 에 남긴다.
- 아래 개체가 언급되면 **반드시 위키링크**로 건다 (실행 시 폴더를 globbing해서 실제 존재하는 이름과 대조):
  - 버티컬 `04-reference/verticals/`
  - 성공사례 `04-reference/cases/`
  - 경쟁사 `04-reference/competitors/` (+ aliases)
  - 기능 `03-playbook/product/features/`
  - 니즈 `03-playbook/sales/needs/`
  - 퍼널 `03-playbook/sales/funnel/`
  - 플랫폼 → `04-reference/플랫폼_연동_현황.md` 의 aliases
- **존재하지 않는 이름으로 링크를 만들지 말 것.** 새 개체는 4장에서 별도 처리.

## 4. 신규 개체 감지 → 제안 (자동 생성 금지)

블록을 읽으며 볼트에 **아직 없는** 개체가 나오면 목록으로 모아 마지막에 **제안**한다. 사용자 승인 없이 만들지 않는다.

| 유형 | 신호 | 만들 위치 |
|---|---|---|
| 성공사례 | 고객사명 + 성과가 함께 언급 | `04-reference/cases/{이름}.md` |
| 경쟁사 | "○○ 쓰고 있음", "○○에서 전환" | `04-reference/competitors/{이름}.md` |
| 플랫폼/WMS | 연동 가능/불가 언급 | `04-reference/플랫폼_연동_현황.md` 표에 행 추가 |
| 버티컬 | 기존 14개에 없는 업종 | `04-reference/verticals/{이름}.md` |
| 용어 | 영문 약어 + 뜻풀이 | `03-playbook/glossary.md` 표에 행 추가 |
| 프레임워크 | 번호 매긴 절차·체크리스트 | `03-playbook/frameworks/{이름}.md` |

제안은 이렇게 보여준다:
```
🆕 새로 발견한 개체 (생성할까요?)
  [사례]   온누리스토어2 — 이벤트 상담량 방어  → 04-reference/cases/
  [경쟁사] 채널메이커      — 월 30만원 CS툴    → 04-reference/competitors/
  [용어]   MQL             — Marketing Qualified Lead → glossary.md
```

## 5. 데일리 노트에 링크 주입

처리한 회사명을 데일리 노트 원문에서 위키링크로 바꾼다.
- `**베니토**` → `**[[베니토]]**`
- `### 제이비케이랩(셀메드)` → `### [[제이비케이랩]](셀메드)`
- 이미 링크된 것은 건너뛴다 (멱등).
- **회사명 외의 본문은 절대 수정하지 않는다.** 사용자가 쓴 원문 표현·오타·강조는 그대로 둔다.

## 6. 결과 리포트

작업이 끝나면 이 형식으로 보고한다:

```
✅ (8.8.)_Lead_Market.md 처리 완료

📁 내 딜 (01-accounts)
  + 새회사A       신규 생성 — next_date 2026-08-11
  ~ 베니토        전략 2줄 추가, 타임라인 갱신

📚 학습 딜 (04-reference/deal-notes)
  + 새회사B       신규 생성 — 커머스-뷰티
  ~ 알앤쇼핑      Risk 1줄 추가

🔗 데일리 노트 링크 주입: 4개
🆕 신규 개체 제안: 사례 1 · 용어 2  (아직 생성 안 함)
⚠️  확인 필요: 새회사C — 내 딜인지 학습용인지 불명확

되돌리기: git checkout {체크포인트해시} -- .
```

마지막에 **깨진 링크 검증**을 반드시 돌린다:
```bash
grep -rhoE '(^|[^!])\[\[[^]]+\]\]' --include="*.md" . | sort -u
```
존재하지 않는 대상으로 링크를 걸었다면 즉시 수정한다.

## 7. 절대 하지 말 것

- ❌ 학습 딜에 `next_action`·`next_date`·`keyman_contact` 넣기
- ❌ 남의 딜을 `01-accounts/`에 넣기
- ❌ 기존 노트 덮어쓰기 (병합만)
- ❌ 사용자 승인 없이 새 허브 노트(사례·경쟁사·버티컬) 생성
- ❌ 데일리 노트의 회사명 외 본문 수정
- ❌ 존재하지 않는 노트로 링크 걸기
- ❌ 없는 정보를 추론해서 채우기 — 빈 필드는 비워둔다
