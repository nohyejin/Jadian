## Core Needs
1. **CS 1인 병목 해소** — *"전화 응대하다 하루 다 감"*, 실질적으로 대응 불가 상태. 퇴사한 CS 포지션을 채널톡으로 대체하는 예산 명목
2. **입주민 / 관리사무소 페르소나 분기 응대** — 관리사무소는 100% 해결 필요, 입주민은 단순 문의·불만 다수 → 규칙·지식·우선순위 분리 요구
   - 예: 로그인 실패 시 관리실은 관리자 계정 확인 후 상담원 연결 / 입주민은 ID·비번 찾기 안내
3. **채널 통합** — 전화·이메일·어드민 게시판·카카오톡 단일 인박스화, 이메일 스팸/광고 필터링, 개발팀 라우팅(현재 매니저 경유 수동 전달)
4. **답변 매뉴얼·아카이빙 부재 해결** — *"아카이빙이 안 되는 게 최우선 과제"*. 문의 유형 분류는 있으나 처리 방법 SOP 전무

## 전략
- **퇴사한 CS 포지션 대체 예산**이라는 명확한 도입 명분 보유
- [[ALF]] 규칙·지식으로 페르소나 분기 설계
- [[수신함-채널통합]]으로 4개 채널 단일 인박스화
- SOP 부재 → [[CoS]]/지식 세팅으로 기반 구축 단계부터 제안

## Risk
- Core Needs가 4개로 분산 → **하나(CS 1인 병목)를 깊게** 가져가는 것이 point
